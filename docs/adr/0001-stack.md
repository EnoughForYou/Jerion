# ADR-0001: Tech Stack Selection & Version Lock

## Status
Accepted

## Date
2026-10-11

## Context
Jerion requires a stable desktop application architecture that provides fast cold-starts, seamless USB/ADB communication, defensive output parsing, and a calm, responsive, non-bloated UI. The project demands strict reproducibility, locked dependencies, and adherence to anti-AI-slop design principles.

## Decisions

### 1. Desktop Shell: Wails v2 (Pinned: v2.16.0)
- **Choice**: Wails v2 (`github.com/wailsapp/wails/v2`), pinned to CLI version `v2.16.0`.
- **Rationale**: Wails v2 is stable, production-ready, and fully fulfills all requirements (single desktop window, Go-to-JS bindings, event emission). Mixing with Wails v3 (`application.New`, `wails3`) is strictly prohibited.
- **Generated bindings**: `frontend/wailsjs/` is auto-generated by Wails CLI and must never be edited manually.

### 2. Backend & System Runtime (Verified via Wails Doctor)
- **Wails CLI**: `v2.16.0`
- **Go Version**: `go1.27.1` (`windows/amd64`)
- **OS Platform**: Windows 11 Pro (Build 26200, 25H2)
- **WebView2 Runtime**: `154.0.4258.62` (Installed)
- **Node.js**: `v26.10.0`
- **npm**: `12.1.0`
- **Hardware Profile**: Intel Xeon E3-1270 v6, NVIDIA GeForce GTX 1650 (Driver: 32.0.16.1714), 16GB RAM
- **Database (Deferred to Phase 2/3)**: Pure Go SQLite (`modernc.org/sqlite`) without CGO to guarantee seamless Windows builds without external GCC/toolchain requirements.
- **OS Secrets (Deferred to Phase 8)**: OS Keychain (`zalando/go-keyring` or platform equivalent).
- **Rule Parser (Deferred to Phase 4)**: `gopkg.in/yaml.v3`.
- *Note*: External Go modules are documented here and will only be added to `go.mod` when implemented to prevent removal by `go mod tidy`.

### 3. Frontend Architecture
- **Framework**: React `19.1.0` (as scaffolded by Wails v2 react-ts template), Vite `7.0+`, TypeScript `5.6+` (`strict: true`).
  - **Rationale for React 19 + R3F 9**: The official Wails v2 `react-ts` template scaffolded React 19 (`^19.1.0`) by default. To preserve the template foundation without forcing artificial downgrades, `@react-three/fiber@9.8.1` and `three@0.186.1` were selected because R3F v9 is designed specifically for React 19 (`>=19 <19.4`). All accompanying libraries (`@tanstack/react-query`, `@tanstack/react-table`, `@tanstack/react-virtual`, `zustand`, `lucide-react`, `react-router-dom`, `react-i18next`) resolve cleanly under React 19 without requiring `--legacy-peer-deps` or `--force`.
- **Styling**: Tailwind CSS `v3.4.19` with PostCSS and Autoprefixer.
  - **Verified Rationale for Tailwind v3**:
    1. Direct mapping of design tokens from `frontend/src/styles/tokens.css` into `tailwind.config.js` using CSS variables (`var(--bg-base)`, `var(--accent)`, etc.).
    2. Reliable, tested PostCSS pipeline integration within standard Vite Wails v2 template.
  - **Tailwind v4 Status**: Compatibility with planned Aceternity UI components under Tailwind v4 is currently **unverified** (*belum diverifikasi*). Potential migration to Tailwind v4 is deferred to a future dedicated ADR.
- **3D Visualization**:
  - `three` (`^0.186.1`) and `@react-three/fiber` (`^9.8.1`).
  - **Peer-Dependency Verification**: `@react-three/fiber@9.8.1` requires `react: ">=19 <19.4"` and `three: ">=0.156"`. Pairing React `19.1.0` with R3F `9.8.1` and Three.js `0.186.1` installs cleanly with zero warnings without `--legacy-peer-deps` or `--force`.
  - Single scene on Home/Scan, lazy-loaded, paused when window loses focus, fallback to SVG.
- **Tooling**:
  - Vitest `5.0.3` with `@testing-library/react` and `jsdom`.
  - ESLint `10.12.0` (Flat config) with `typescript-eslint`.
  - Prettier `3.9.10` with `endOfLine: "lf"`.
- **State Management**:
  - TanStack Query (`@tanstack/react-query`) for asynchronous Go bindings state.
  - Zustand (`zustand`) for synchronous UI/client state.
- **Tables & Virtualization**: `@tanstack/react-table` and `@tanstack/react-virtual` for smooth 500+ package rendering.
- **Routing**: React Router (`react-router-dom`) configured with `HashRouter` (assets served locally by Wails).
- **Icons**: `lucide-react` (single icon family).
- **i18n**: `react-i18next` + `i18next` configured for English-only (`en.json`) in v1.

## Consequences
- Clean separation between thin `app.go` and internal packages.
- Zero npm peer-dependency conflicts during installation.
- Stable, reproducible build pipeline across developer environments and CI.
